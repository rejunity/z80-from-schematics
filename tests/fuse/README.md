# FUSE Z80 instruction tests

The canonical per-opcode test corpus for the Z80 — **1356 cases**, one (or
more, for the conditional and repeating variants) per opcode. Authored by
**Philip Kendall in 2006** for the FUSE Spectrum emulator; the files are
byte-identical to FUSE's `z80/tests/` (GPL v2, see
[THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)).

> **Provenance.** This corpus is often misattributed to Frank D. Cringle,
> whose `zexall.com` / `zexdoc.com` exercisers (tests/zex/) were
> checksummed on a real Z80. FUSE's expected values were generated by
> FUSE's own core and never validated against silicon. We now check every
> case on the die itself: `make fuse_pz80` (below) runs the corpus on
> perfectz80, the transistor netlist of the Zilog NMOS die, and the die
> agrees with `tests.expected` on 1350 of the 1356 cases.

We run it three ways, each against the same expected values:

  - `make fuse`      — through the C model ([`scripts/fuse_runner.c`](../../scripts/fuse_runner.c)) → **1356 / 1356**
  - `make fuse_rtl`  — through the RTL via iverilog ([`scripts/gen_fuse_tb.py`](../../scripts/gen_fuse_tb.py) + [`scripts/compare_fuse_rtl.py`](../../scripts/compare_fuse_rtl.py)) → **1356 / 1356**
  - `make fuse_pz80` — on the die ([`scripts/fuse_pz80.c`](../../scripts/fuse_pz80.c), ~1.5 min) → **1356 / 1356**

The expected values are `tests.expected`'s, except for the six cases in
[`silicon.expected`](silicon.expected), where the die ends in a different
state than FUSE says; all three runners take those six from there. No case
is skipped and no failure is tolerated.

| Case | Instruction | FUSE expects | The die (and the models) |
|------|-------------|--------------|--------------------------|
| `76` | HALT | PC = 0000, the HALT byte | PC = 0001: the die's PC moves past the HALT; the halted M1s fetch from there and an interrupt pushes it |
| `edb2_1` | INIR, B not reaching 0 | F = 0C, WZ = BC + 1 | F = 00, WZ = 0001 |
| `edba_1` | INDR, B not reaching 0 | WZ = BC - 1 | WZ = 0001 |
| `edb3_1` | OTIR, B not reaching 0 | F = 17, WZ = BC + 1 | F = 03, WZ = 0001 |
| `edbb_1` | OTDR, B not reaching 0 | F = 17, WZ = BC - 1 | F = 03, WZ = 0001 |
| `edb9_2` | CPDR, repeating | F = A7 | F = AF |

A repeating block instruction's extra 5-T cycle sets WZ = PC + 1 and its
flags: X and Y from PC's high byte, and for the I/O repeats H and P/V from
one more step of the B calculation (David Banks, 2018; z80memptr and
z80flags check the same). These six were the "known-FUSE-wrong" list the
runners used to skip, with two more: `37_1` (SCF) and `3f` (CCF). Those two
were the runners' fault: they started every case with Q (the flags the
previous instruction wrote, which SCF / CCF read X and Y from) equal to F.
On the die, after loading the registers, Q is 0, and FUSE's values for
both are the die's. The runners start every case with Q = 0 now.


## Files

| File               | Lines | What it is                                                                   |
|--------------------|------:|------------------------------------------------------------------------------|
| `tests.in`         |  9153 | one record per test case: name, registers, IFF / IM / HALTED / target tstates, initial memory |
| `tests.expected`   | 18913 | one record per test case: per-cycle bus-event list, final registers, final state, final memory |
| `silicon.expected` |    41 | the die's final state for the six cases above, in `tests.expected`'s format without the bus events; `#` lines are comments |


## File format

Records are blank-line-separated. Each record begins with a lowercase opcode
name (e.g. `dd cb 01 46` flavours are named `ddcb01_46`).

`tests.in` record:

    name
    af bc de hl af' bc' de' hl' ix iy sp pc memptr     (13 × 4-hex)
    i r iff1 iff2 im halted target_tstates             (initial state line)
    addr  byte byte byte ...  -1                       (zero or more memory blocks)
    -1                                                  (record terminator)

`tests.expected` record:

    name
    «cycle» «op» «addr» [«data»]                       (per-cycle events: MC=mem contend, MR=mem read,
                                                        MW=mem write, PC=port contend, PR=port read,
                                                        PW=port write)
    af bc de hl af' bc' de' hl' ix iy sp pc memptr     (final registers)
    i r iff1 iff2 im halted final_tstates              (final state)
    addr  byte byte byte ...  -1                       (zero or more memory blocks)
    (blank line)


## Runners

Every runner starts a case with all memory zero except the case's own
bytes, port reads returning the high byte of the address bus (FUSE's
convention) and Q = 0, runs to the case's final T-state count, and
compares the registers, WZ, I, R, the T-states and every memory byte the
expected record lists.

  - `scripts/fuse_runner.c` (C model) also compares IFF1, IFF2, IM and
    HALTED. Exit 1 on any difference, or when a case of
    `silicon.expected` names no case of the corpus.
  - `scripts/gen_fuse_tb.py` + `scripts/compare_fuse_rtl.py` (RTL) build a
    single `tests/iverilog/tb_fuse.v` with every case inlined, compile it
    with iverilog, run `vvp`, and compare in Python. The testbench reads
    back every byte that the case's input or its expected record names,
    and zeroes the bytes a case set or wrote before the next one. A case
    with no result, or an expected byte not read back, fails the run.
  - `scripts/fuse_pz80.c` (the die) runs each case on perfectz80 behind
    a preamble that loads its registers (POPs, `LD I,A`, `LD R,A` counted
    back over the M1s that follow, `LD A,(WZ-1)` for WZ, `IM n`, `EI` or
    `DI`) and falls into the case's instruction; its last instructions
    are `POP AF` and `LD SP,nn`, so the case starts with Q = 0. It reads
    the registers from the die's nodes in T4 of the M1 that follows the
    case (the die writes some results in that M1's T1-T3), PC as the
    address that M1 fetches and R from its refresh address, and checks
    that this M1 starts exactly the case's T-state count after the
    case's own. Not read back on the die: IFF1, IFF2 and IM (the four
    RETN cases that start with IFF1 != IFF2 run with IFF1 = IFF2; nothing
    read back depends on IFF1).

None of them compares the per-cycle bus events (MC / MR / MW ...): the
pin sweeps against perfectz80 (`make event_sweep`, `make pin_scenarios`)
compare the whole bus, every half-cycle.


## What FUSE catches that ZEXDOC / ZEXALL don't

  - **Per-opcode T-state count** (ZEXALL only checks final state).
  - **WZ (MEMPTR), I and R** after every case.
  - **Memory per case** (ZEXALL CRCs the result; FUSE itemises the
    affected bytes, which makes it much easier to localise a bug).
